## 1 版本升级

### 1.1 v3、v4 能否直接升级到 v5？

**问题**：v3、v4 各版本能否直接升级到 v5？

**处理方式**：

- **v4 升级 v5**：v4 到 v5 的数据库迁移连续可前滚，v4 各版本可直接升级到 v5，无需额外前置操作。若当前为较早期的 v4.0.0 版本，建议先升级到 v4 最新版本（v4.10.19 LTS）再升级到 v5。
- **v3 升级 v5**：无法一步到位。需先将当前版本升级到 v3 最新版本（v3.10.23 LTS），再升级到 v4，最后升级到 v5，否则会因表结构变更导致升级失败。

详细升级步骤与离线包下载地址，请参阅[升级指南](../installation/setup_linux_standalone/offline_upgrade.md)。

### 1.2 升级到 v5 后页面打不开，提示 400 / 403？

**问题**：升级到 v5 后无法打开页面（登录界面），浏览器提示错误码 400 或 403。

**处理方式**：需要填写 `DOMAINS` 可信任域名。打开 `/opt/jumpserver/config/config.txt`，按实际访问方式配置 `DOMAINS` 字段。v5 中 `DOMAINS` 取值需要带上端口（HTTPS 使用 `443`，HTTP 使用 `80`），多个地址之间使用英文逗号分隔，修改后重启 JumpServer 服务：

```sh
vim /opt/jumpserver/config/config.txt

# 使用域名访问（HTTPS）
DOMAINS="demo.jumpserver.org:443"
# 使用 IP 访问（HTTP）
DOMAINS="172.17.200.191:80"
# 同时使用域名与 IP 访问
DOMAINS="demo.jumpserver.org:443,172.17.200.191:80"

# 重启 JumpServer 服务生效
jmsctl restart
```

- 若服务器为一键安装，且旧版本已使用 JumpServer 开启 HTTPS，则无需修改。
- 使用 IP 地址访问 JumpServer 时，请根据实际网络环境填写公网 IP 或内网 IP。

### 1.3 升级到 v5 后发现没有 lion 组件？

**问题**：v5 的容器编排文件或组件列表中看不到 lion 组件。

**处理方式**：v5 中 lion 的功能已合并到 koko。升级后若组件列表中残留处于离线状态的 lion，可在「系统设置 → 组件列表」中将其删除。

### 1.4 v4.10.16 升级到 v5 后 Web 终端功能缺失怎么办？

**问题**：从 v4.10.16 升级到 v5 后，Web 终端界面变得极简，缺少资产树、文件传输等功能，如何恢复完整功能？

**处理方式**：

JumpServer v5 版本对 Web 终端进行了重构，默认进入的是“纯净模式”（仅显示远程画面）。要恢复包含资产树、文件传输等功能的完整界面，请按以下步骤操作：

1. **切换视图模式**：在 Web 终端页面的右上角，点击 **Web 终端** 按钮（或类似图标），即可从纯净模式切换回带资产树的完整工作台界面。
2. **检查组件状态**：v5 版本中，原 Lion 组件的功能已合并至 KoKo 组件。请确保 KoKo 组件运行正常。
3. **验证配置**：进入 **系统设置** > **组件设置**，确认 **客户端连接**、**密码**、**SSH 公钥** 等选项已启用，以确保 Web 终端功能正常加载。

若界面仍显示异常，建议检查浏览器缓存或尝试清除缓存后重新登录。

更多组件配置详情，请参阅[组件设置](../manual/admin/system_settings/components.md)。

## 2 环境与数据库要求

JumpServer 对操作系统内核、数据库与缓存的版本要求，详见[环境要求](../installation/setup_linux_standalone/requirements.md)。

### 2.1 内核版本低于 4.0 能否升级？

**问题**：机器的 Linux 内核版本低于 4.0，能否升级？

**处理方式**：JumpServer 要求 Linux 内核 >= 4.0（amd64、arm64 架构均为该要求），内核版本低于 4.0 无法直接升级。建议先升级操作系统内核，或将数据迁移至满足要求的机器后再进行升级。

### 2.2 v5 对数据库版本有什么要求？MySQL 5.7 还能继续使用吗？

**问题**：v5 对数据库版本有什么要求？原来使用的 MySQL 5.7 是否还能继续使用？

**处理方式**：v5 要求 MySQL >= 8.0、PostgreSQL >= 16、MariaDB >= 10.6，缓存要求 Redis >= 7.0；安装时默认使用内置的 PostgreSQL 与 Redis。若原环境使用 MySQL 5.7，需先升级到 8.0 及以上版本。

## 3 功能变更与限制

### 3.1 v5 Web远程应用是否支持脚本代填？

**问题**：在 v5 版本中，Web 远程应用（RemoteApp）是否支持脚本形式的密码代填？

**处理方式**：

根据官方文档，JumpServer 的远程应用（RemoteApp）功能主要依赖 **应用发布机** 环境来运行 Web 页面资产或连接数据的程序。

1. **功能依赖**：远程应用需准备应用发布机（Windows Server 2019 或 Linux 虚拟应用）来支持。社区版仅支持 Web GUI 方式，本地客户端连接（MSTSC）需 X-Pack 授权。
2. **配置方式**：文档中未提及 Web 远程应用支持自定义“脚本”进行代填。远程应用的连接与账号管理主要通过 **应用发布机** 的 **账号列表** 和 **自动创建帐号** 等参数进行配置。
3. **虚拟应用**：若使用 Linux 作为远程应用载体，需在 **系统设置 > 功能设置 > 虚拟应用** 中开启，具体配置见虚拟应用文档。

若遇到代填问题，请检查应用发布机的账号配置及协议（WinRM/OpenSSH）是否正确部署，而非依赖脚本。

详细的应用发布机创建与参数配置，请参阅 [远程应用](manual/admin/app_management/remote_apps.md) 和 [虚拟应用配置说明](manual/admin/app_management/virtual_apps.md)。[../manual/admin/app_management/remote_apps.md](../manual/admin/app_management/remote_apps.md)

### 3.2 v5 Web终端选中文字自动复制功能去哪了？

**问题**：在 v5 版本的 Web 终端中，选中文字后不再自动复制到剪贴板，之前 v3/v4 有这个功能，现在怎么恢复或替代？

**处理方式**：

JumpServer v5 的 Web 终端设置中未提供“选中即复制”的独立开关。根据官方文档，v5 版本 Web 终端的复制粘贴行为主要依赖以下机制：

1. **右键快速粘贴**：在 **设置 > 通用** 页面中，开启 **右键快速粘贴** 后，在命令行终端中右键可直接粘贴剪贴板内容。
2. **手动复制**：文档未提及自动复制功能，建议通过选中文字后使用键盘快捷键（如 `Ctrl + C`）或右键菜单进行手动复制。

若需确认具体版本的功能差异或获取最新行为说明，请以官方文档为准。

详细配置项说明，请参阅 [Web 终端设置](manual/user/web_terminal/settings.md)。[../manual/user/web_terminal/settings.md](../manual/user/web_terminal/settings.md)
